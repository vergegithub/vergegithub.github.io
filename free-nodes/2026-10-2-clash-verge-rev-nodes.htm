一、为什么选择Quantumult作为去广告利器？

在App Store中，广告拦截工具并不少见，如AdGuard、BlockBear等均能提供基础的屏蔽功能。但Quantumult的独特之处在于，它并非一个“单一功能”的拦截器，而是一个高度可定制的网络代理内核。这意味着，您不仅能通过它过滤网页中的广告元素，还能同时管理HTTPS流量解密、制定精细的域名分流规则、甚至实现基于地理位置的智能代理切换。更重要的是，Quantumult的广告过滤并非依赖内置的简单黑名单，而是通过加载外部规则资源（如AdBlock语法规则、Hostname列表、正则表达式等）来实现动态更新与精准匹配。这种灵活性，使得它能够应对不断变异的广告形式——从传统的横幅广告到如今复杂的动态脚本注入，Quantumult都能通过自定义配置进行有效拦截。

此外，Quantumult对系统资源的占用极低，在后台运行时几乎不会影响设备续航。其基于Network Extension框架的设计，使得所有过滤操作均在本地完成，既保护了用户隐私，又规避了云端过滤带来的延迟。因此，对于追求极致网络体验、又希望掌控数据流向的高级用户而言，Quantumult无疑是最优解。

三、手把手配置：Quantumult去广告全流程

3.1 第一步：导入配置文件与基础设置

打开Quantumult应用，您会看到一个简洁的主界面。首次使用时，建议先进行“配置”的初始化：

  • 点击右下角的“配置”（或“Config”）标签页。
  • 在弹出的界面中，选择“本地配置”，点击右上角的“+”新建一个配置文件。
  • 为文件命名，例如“MyAdBlock.conf”。此时，系统会生成一个空白配置模板。

接下来，您需要编辑该文件，添加关键的过滤规则。Quantumult支持两种配置方式：文本编辑（适合进阶用户）与资源引用（适合快速部署）。对于大多数用户而言，推荐使用“资源引用”方式，因为它允许您直接添加远程规则URL，并支持定期自动更新。

在配置文件的编辑界面中，找到[filter]或[filter_remote]字段。若不存在，可手动添加。在此字段下，您需要添加远程规则的引用格式：

https://example.com/adblock.txt, tag=AdBlock, enabled=true

其中，tag为规则标签（可自定义），enabled控制是否启用。为了获得最佳效果，建议同时添加2-3个互补的规则源。例如：

https://raw.githubusercontent.com/AdguardTeam/AdguardFilters/master/BaseFilter/sections/adservers.txt, tag=AdGuard_Base, enabled=true https://raw.githubusercontent.com/AdguardTeam/AdguardFilters/master/ChineseFilter/sections/adservers.txt, tag=AdGuard_CN, enabled=true https://raw.githubusercontent.com/ConnersHua/Profiles/master/Quantumult/X/Filter/Rewrite.list, tag=ConnersHua_Rewrite, enabled=true

添加完毕后，点击右上角“保存”。此时，Quantumult会尝试下载并解析这些规则。您可以在“配置”页面看到规则列表的加载状态。

3.2 第二步：开启HTTPS解密（MITM）功能

现代广告大量使用HTTPS协议进行加密传输，仅靠普通的URL匹配无法拦截隐藏在加密流量中的广告请求。因此，Quantumult提供了“MITM”（中间人攻击）解密功能。请注意：开启此功能后，Quantumult会生成一个本地CA证书，您需要信任该证书才能实现对HTTPS流量的深度检查。

操作路径如下：

  • 返回主界面，点击“设置”（或“Settings”）。
  • 找到“MITM”选项，将其切换为开启状态。
  • 点击“证书管理”，选择“生成新证书”，并按照系统提示安装到描述文件中。
  • 随后，进入iOS的“设置” -> “通用” -> “关于本机” -> “证书信任设置”，找到Quantumult生成的证书，将其开启为“完全信任”。

完成上述步骤后，Quantumult将能够解密并分析HTTPS流量。但请注意，MITM功能仅用于广告过滤与隐私保护，并不会记录您的浏览内容。

3.3 第三步：配置重写（Rewrite）规则以去除页面元素

除了网络层拦截，Quantumult还支持“重写”功能，即通过正则表达式修改网页的JavaScript或HTML代码，从而隐藏广告占位符或跳过视频贴片广告。这一功能尤其适用于去除那些无法通过域名拦截的“原生广告”。

在配置文件的[rewrite_remote]字段下，您可以添加重写规则。例如：

https://raw.githubusercontent.com/ConnersHua/Profiles/master/Quantumult/X/Rewrite/AdBlock.list, tag=Rewrite_AdBlock, enabled=true

该规则集包含了对常见视频网站、新闻客户端广告脚本的精准替换代码。保存后，Quantumult会自动应用这些重写规则。

3.4 第四步：启用“广告屏蔽”开关并测试

当所有规则加载完毕后，请检查以下设置以确保广告过滤生效：

  • 进入“设置” -> “通用”，确认“广告过滤”（或“Filter Advertisements”）选项为绿色开启状态。
  • 返回主界面，点击“开始”按钮启动代理服务。此时，状态栏会出现VPN图标，表示Quantumult正在工作。

为了验证效果，建议您访问几个广告密集的网站，例如： - 新闻门户：新浪、网易、腾讯 - 视频网站：Bilibili、YouTube（需配合代理） - 技术社区：CSDN、知乎（部分广告为信息流形式）

如果发现仍有广告残留，可尝试以下优化： 1. 更新规则：在“配置”页面下拉刷新，强制重新拉取远程规则。 2. 增加规则源：在[filter_remote]中追加更严格的列表，如https://raw.githubusercontent.com/AdguardTeam/AdguardFilters/master/SearchFilter/sections/tracking_servers.txt。 3. 自定义过滤：对于特定广告域名，可在[filter]字段手动添加host, ad.example.com, reject。

四、进阶技巧：让去广告更智能、更高效

4.1 按需分流，避免误杀

有时候，过度激进的过滤规则会导致部分正常功能（如评论区加载、社交分享按钮）失效。此时，您可以利用Quantumult的“分流”功能，将特定域名排除在过滤范围之外。例如，在[filter_local]中添加：

host, *.google-analytics.com, direct

这表示对Google Analytics的请求直接放行，不进行广告拦截。通过合理的“白名单”策略，您可以在屏蔽广告与保留功能之间找到完美平衡。

4.2 使用“策略组”实现场景化过滤

Quantumult允许您创建不同的“策略组”，每个组可以绑定不同的过滤规则。例如，您可以设置一个“工作模式”策略组，在该模式下仅启用隐私保护规则，而关闭娱乐网站的广告过滤；再设置一个“浏览模式”策略组，启用全部广告拦截规则。通过主界面的策略切换，您可以在不同场景下快速调整过滤强度。

4.3 配合DNS过滤，阻断广告域名解析

除了在应用层过滤，Quantumult还支持自定义DNS服务器。通过配置如system或https://dns.alidns.com/dns-query，您可以阻止广告域名的DNS解析。在[dns]字段中添加：

server = system server = https://dns.alidns.com/dns-query

同时，在[filter]中将广告域名指向reject，即可在解析阶段直接阻断，极大提升过滤效率。

五、常见问题与解决方案

5.1 Quantumult无法拦截视频广告怎么办？

视频广告（如YouTube的贴片广告）通常采用动态加密的播放协议，仅靠静态规则难以完全匹配。此时，建议您： - 确保已开启MITM解密，并信任证书。 - 添加专门针对视频网站的重写规则，例如https://raw.githubusercontent.com/yichahucha/surge/master/youtube_adblock.sgmodule（需转换格式）。 - 尝试更换节点，某些节点可能通过IP黑名单直接屏蔽广告服务器。

5.2 开启Quantumult后，部分App无法联网？

这通常是因为MITM证书未被信任或规则误伤了某些API域名。解决方法： - 检查证书信任设置，确保“完全信任”已开启。 - 在[filter_local]中添加host, api.example.com, direct，放行必要的接口。 - 暂时关闭MITM，检查是否恢复正常，以判断是否为证书问题。

5.3 去广告规则更新后，效果反而变差？

规则更新有时会引入不兼容的条目，导致过滤失效。建议： - 在“配置”页面长按规则标签，选择“停用”该规则，观察效果是否恢复。 - 回退到之前的规则版本，或删除最近添加的规则源。 - 加入Quantumult官方Telegram群组，向其他用户反馈问题，获取应急补丁。

WinXray PAC 模式如何提高访问速度和便利性？
PAC 模式根据规则动态判断流量是否走代理，无需手动切换节点。适合国内外混合访问场景，提高网页和视频访问速度与稳定性，减少操作错误导致的访问失败。
Hysteria2 的多路复用功能有哪些优势？
多路复用允许多个请求共享同一 QUIC 连接，减少握手次数和延迟。高并发情况下可以提升吞吐量和稳定性，特别适合短连接频繁请求的应用，如游戏或即时通讯。
如何防止租用服务器被用作滥发或代理滥用？
限制对外端口与协议，使用防火墙与入侵检测（如 fail2ban），监控流量异常并设置告警，定期审计登录行为，及时阻断滥用源并与服务商沟通封禁滥用账户以防引起供应商封禁整台机。
